# 上线自查清单

[English](launch-checklist.md) · [简体中文](launch-checklist.zh.md)

说完成之前、部署之前、提交商店之前，过一遍这张表。它是从 [doaipm 手册](https://doaipm.com/zh/presale/)上线那一章压缩出来的，来源是四个上线产品和三次 App Store 被拒。

每一条背后是同一个原则：**成功要从外部世界读回来，不能由自己判定。** AI 对报错路径处理得很好，它防不住的是不报错的失败：打包成 .app 后三个功能一起失效；配置文件带了 BOM，全部设置被静默清空；`--lang ko` 静默回退成中文。这三次单元测试全绿。

## 1. 声明完成之前的自查

跑一遍真流程，不只是跑测试。每个功能：

- [ ] **数据往返。** 造测试数据 → 驱动功能 → 读回结果断言，只改了该改的
- [ ] **UI 路径。** 把应用真跑起来，驱动真实界面，截图核验
- [ ] **单元测试。** 涉及哪层跑哪层
- [ ] **干净的最小 diff。** 扫一眼 `git diff`，格式化了整个文件、改了不相干的缩进、删了它认为没用的代码，一眼就能看见
- [ ] **CLI / MCP 冒烟**（如果产品带这两样）：新能力同步暴露出去
- [ ] **多语言。** 新字符串进主语言，其余语言补占位
- [ ] **高保真检查。** 真内容、四种状态（加载 / 空 / 出错 / 成功）、真交互、主流程走通、窄屏、刁钻输入。见[阶段 5 · 验证](../method/05-validate.zh.md)

**红线：自测未过不得声明完成。** 确实没法自动化测的，退到低一级（比如状态层断言加截图核验），并且把退到哪一级写下来。允许降级，不允许跳过。

## 2. 相信任何「成功」之前

- [ ] **成功是谁判定的？** 代码自己判定的成功，换成去真实目标上读回来
- [ ] **这一步会不会点错对象？** 靠文本、位置、序号定位，后面跟着写操作或撤不回的点击，由人接管（`Publish` 匹配到 `Published` 就是真事）
- [ ] **结果 AI 看得见吗？** 打包产物、真机、上架审核、外部服务，由人验一次
- [ ] **会重复跑的流程配一个开跑前体检**，里面至少有一次真实动作（比如真点一下），先证明工具链是好的，再开跑

## 3. Web 上线

- [ ] 部署就是一次 push（比如 Cloudflare Pages 从主分支自动构建）
- [ ] **等到真的返回 200 再宣布上线。** 边缘节点不是同时铺开的。实测一次部署：push 后约 60 秒页面开始返回 200，其中一个语言的页面又多返回了约一分钟 404

```bash
until [ "$(curl -s -o /dev/null -w '%{http_code}' https://你的域名/路径)" = "200" ]; do
  sleep 15
done
echo LIVE
```

## 4. App Store 上架

三次被拒收成的检查表。其中两次出在元数据和配置上，跟功能代码无关；第三次是审核员走最朴素的路径，卡在了文件选择器上。

| 检查项 | 为什么 |
|---|---|
| [ ] 副标题、关键词、宣传文案、描述，**以及截图上的字**，没有价格词（「免费」之类） | 条款 **2.3.7**（元数据准确）。FreeID Photo 第一张截图的大标题写着 "Truly free"，被拒 |
| [ ] 用了摄像头、人脸、健康、位置数据？隐私页和审核备注正面回答苹果的问题 | 条款 **2.1**。FreeID Photo 用 Vision 做人脸检测，修复是加一个「人脸数据」小节：在设备上处理、不存储、不共享、不留存 |
| [ ] **拿签名后的正式包，在干净环境里启动一次** | 条款 **2.1(a)**。SoloPDF 的 Mac 版在审核员那里打开是白屏：沙盒少了 `com.apple.security.network.client`。开发模式不走沙盒，所以本机一切正常 |
| [ ] **走一遍最朴素的用户路径**：打开 → 选文件 → 用 | 条款 **2.1(a)**。SoloPDF 的 iOS 版，文件选择器返回 `file://` URL，选中的任何 PDF 都打不开 |
| [ ] Mac App Store 包里没有裸的嵌套可执行文件 | 校验错误 **90049 / 90885**（SoloPDF 在包里嵌了一个命令行程序） |
| [ ] 扩展属性清干净了（`xattr -cr`） | 校验错误 **91109** |
| [ ] Mac App Store 版本**关掉** hardened runtime | 跟沙盒冲突，提交会被拒 |
| [ ] 审核备注里写了修复的根因、示例文件、支持页面 | 能省一轮来回 |

三个在下一个 App 上会还回来的习惯：

- **上架做成一条命令。** 改版本号、跑测试、归档、上传、等处理完、写元数据、提交审核。元数据集中放在一个文件里。三次被拒有两次是「改元数据、同一个 build 重新提交」，有脚本就是改一行
- **工具链要能把被拒的版本重新当成可编辑的。** 被拒之后版本状态会变，脚本不认这个状态就没法重新提交
- **重新提交前，把审核员的操作路径原样走一遍。** SoloPDF 的修复先在 iPad 模拟器上复现审核员的路径，再在 iPhone 模拟器上端到端验证

## 5. 上线之后

- [ ] 定期亲眼去每个渠道看：真实阅读、评论、账号状态。脚本每天报「已发布」，一个死了一个月的渠道就这么藏住了
- [ ] 两个人以上一起做的，写下来谁负责哪几个目录
