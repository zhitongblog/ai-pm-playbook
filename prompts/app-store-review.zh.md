# 上架前对照常见被拒原因审一遍元数据

[English](app-store-review.md) · [简体中文](app-store-review.zh.md) · [全部提示词](README.zh.md)

**什么时候用：** iOS 或 Mac 应用提交审核之前；或者被拒之后、重新提交之前。

这些检查项来自三次真实的被拒（条款 2.3.7、2.1、2.1(a)）和两次打包校验失败。大部分不在代码里，有几项 AI 根本看不见，所以提示词最后列了必须你亲手查的部分。

```
按 App Store 提交的要求审一遍这个应用。看元数据文件、截图上的文字、entitlements、
隐私页、构建和打包脚本。每一项报告 通过 / 不通过（写出具体文件和原文）/ 查不了（说明原因）。

1. 价格词：名称、副标题、关键词、宣传文案、描述（每个语言都看），以及截图上画的字里，
   有没有「免费」「free」之类的价格说法？（条款 2.3.7）
2. 敏感数据：应用用没用摄像头、人脸检测、健康、位置之类的数据？隐私页有没有讲清楚
   这些数据怎么处理、存不存、共不共享、留不留？起草审核备注里的回答。（条款 2.1）
3. 沙盒权限（Mac）：对照应用启动时实际要做的事检查 entitlements，
   比如 App Sandbox 下 WebView 需要 com.apple.security.network.client。（条款 2.1(a)）
4. 文件处理：文件选择器或「打开方式」返回 URL 的地方，用之前有没有转成普通路径？（条款 2.1(a)）
5. Mac App Store 包里有没有裸的嵌套可执行文件（比如命令行辅助程序）？（校验 90049 / 90885）
6. 打包脚本有没有清扩展属性（xattr -cr）？（校验 91109）
7. Mac App Store 版本有没有关掉 hardened runtime？（跟沙盒冲突）
8. 起草审核备注：应用做什么、审核员能用的示例文件、支持页面、之前被拒的根因。

先什么都别改，把报告给我。
```

**然后亲手查这几样，AI 看不见：**

- 把**签名后的正式包**装到干净环境里，启动一次
- 像审核员一样走最朴素的路径：打开应用 → 选一个文件 → 用
- 每一张截图自己看一遍
