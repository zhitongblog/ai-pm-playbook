# 用真内容和四种状态自测

[English](self-test-four-states.md) · [简体中文](self-test-four-states.zh.md) · [全部提示词](README.zh.md)

**什么时候用：** AI 说某个功能做完了。在你相信它之前。

「做完了」不等于「做好了」。下面这些检查跑的是真东西，不只是单元测试，而且每一项都要 AI 把结果拿给你看，而不是告诉你「通过了」。

```
在说完成之前，把应用跑起来，按这张清单逐项过一遍。
每一项：真的跑一遍，给我看证据（截图、输出，或者你具体做了哪几步），没过的当场修。

1. 真内容：还有没有 Lorem ipsum、「示例文字」、占位？换成像样的真实内容和真实数据结构。
2. 四种状态：主界面的加载中、空数据、出错、成功，四种都给我看。通常缺的是空和错。
3. 真交互：每个按钮能点，每个表单能提交，每个链接能跳。不能只是看起来能用。
4. 关键路径：把用户最重要的那条主流程从头到尾走一遍。
5. 窄屏：按手机宽度看一遍。
6. 刁钻输入：输错、输空、输超长、贴奇怪字符，崩不崩？
7. diff：给我看 `git diff --stat`，指出跟这个功能无关的改动，把它们退回去。

没跑过的项不许说通过。确实没法自动测的，说清楚你退到了哪一级检查。
全部通过之前不算完成。
```

**如果做的是 AI 功能，再加一条：**

```
8. 给这个 AI 功能写 12 条真实又刁钻的输入（包括专门想让它出错、让它胡编的）。
   连着全部跑一遍，把每条输入和输出给我看，标出不一致、答错、错得很难看的地方。
```

然后做提示词替你做不了的那一步：交给别人用，自己闭嘴，看他卡在哪。
